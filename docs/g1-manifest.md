- 作成: 2026-09-20（旧プロジェクト）。2026-09-21 にトレイ (0.22, ±0.09) の配置で作り直し、両物体の開始位置を試行ごとに固定した。2026-10-27 に課題用に書き直した
- 正本: `contracts/fixtures/g1/manifest.json`。判定値: `src/so101_demo/execution/criteria.py`。実行: `src/so101_demo/evidence/stage1_g1.py`。規則の確認: `src/so101_demo/plan/manifest.py`（`check_manifest`）と `tests/test_g1_manifest.py`

## 結論
- 固定 10 試行の manifest は、4 組合せ（red_cube / blue_cube × box_a / box_b）を各 2〜3 回、対象は毎回切替、**赤・青の両方**の開始 xy を試行ごとに固定する。どちらの物体も home に留まらない
- 開始位置は**ユーザーが描画で確認して 10 パターンを決め**（2026-09-20）、エージェントは規則（作業領域内・中心間距離 ≥ 60 mm・トレイ足元と重ならない・把持 TCP が作業領域内）と headless 実行で確認する。開発試行の結果に合格数字を合わせない
- 受け入れ実行（GPU 機、2026-09-21、`MUJOCO_GL=egl --label 受け入れ --video`）: **10/10 成功**、開始配置 合（誤差 0.11 mm）、他物体の移動 0.00 mm、実行後リセット 合、失敗なし。先行する headless 参考実行（同日、laptop）と全数値が一致する（決定的）。記録と動画はこのリポジトリに持ち込んでいない（下の「受け入れ実行」に要約を残す）
- 配置の根拠（幾何のみ、sim 実行なし、2026-09-21）: 立方体が立てる格子点 / 2 物体の配置（無順序の組）= (0.19, ±0.085) 56 / 251、**(0.22, ±0.09) 68 / 807**、(0.23, ±0.09) 80 / 1405。旧配置 (0.19, ±0.085) では 10 パターンのうち 9 つが規則違反（T04 のみ可）で、配置変更なしにはこの manifest は作れない

## 開始位置の決め方（2026-09-20 のユーザー決定）
1. ユーザーが描画で配置を確認し、10 パターンを決める
2. エージェントは規則（上表 (d)）を `check_manifest` で確認し、headless 参考実行で 10 試行を通す
3. 通らない試行があればその事実と数値を記録し、パターンの差し替えはユーザーに決めてもらう（エージェントは成功する位置を探し直さない）

### T07 の (0.16, 0.00) について
P07 は当初 (0.16, 0.00) が headless で `not_seated` だったので (0.16, −0.01) にずらした。2026-09-21 に同じ開始位置を今のコードで確認したところ、**(0.16, 0.00) でも success**（解放後 中心 (0.2185, −0.0889)、傾き 0.00°）になった。間に入った変更は置き姿勢の整合（`docs/place-margin.md`、2026-09-20）である。manifest は (0.16, −0.01) のままにした（開始位置はユーザーの決定であり、エージェントが結果を見て戻さない）。

## 既知の性質と未評価の範囲
- 閉指令時の立方体は TCP から約 29.6 mm にある（降下時に固定顎が約 6 mm 押すため。今も同じ）。**2026-09-20 の置き姿勢整合より前**は、手先の向きが基部から径方向に固定されていたので置き先で把持方向が方位角の分だけ回り、回転が大きく offset が壁側へ向く組合せは `not_seated` になり得た。当時の旧配置の sweep 50 run では `not_seated` が 6 run あり、隣接格子点で成否が変わる例（blue (0.22, 0.02) 成功 / (0.22, 0.01) 失敗）もあった。現行の `PickPlace.place` は置き先の yaw（トレイは 0 = base の +x）で顎の向きを指定し、持ち上げ後に測った把持オフセットで置き TCP を補正する（`docs/place-margin.md`）
- 新配置 + 置き姿勢整合の後、この 10 試行はすべて成功し、解放後の中心のずれは **x −1.00〜−1.53 mm、平面距離 最大 2.72 mm** に収まっている
- 実施済み（2026-09-20、`docs/place-margin.md`）: 規則を満たす 10 mm 格子の開始点 × 2 物体 × 2 置き先で**非対象を home に置いた** 94 run が全 success（着地余裕 最小 5.6 mm）、y = 0 列（x 16〜23 cm、対象のみ配置）32 run も全 success
- 未評価: **両物体を任意の格子点に置く組合せ**（本 manifest の 10 パターン以外）。旧配置で見えた「隣接格子点で成否が変わる」性質がこの範囲で消えた証拠はない
- 60 mm 規則の限界（現行規約では可動顎は base の +x に開くので、非対象が対象の +x 側 60 mm にあると当たることがある。置き姿勢整合前の旧配置の sweep で 16〜51 mm 動いた例あり）は規則として残っている。この 10 パターンでは最小の中心間距離が 72 mm で、実測の他物体の移動は 0.00 mm

## 凍結の手順
1. `main` 上の `contracts/fixtures/g1/manifest.json` を含む commit のハッシュを Issue にコメントした時点で凍結。以後は書き換えない
2. 受け入れ実行は、そのハッシュの manifest（差分なし）で `MUJOCO_GL=egl uv run python -m so101_demo.evidence.stage1_g1 --approve-fixed-fixture --label 受け入れ --video` を実行し、`trials.md` の「commit」欄がそのハッシュ（完全形）を示すことを確認する（`stage1_g1` は、manifest を最後に変えた commit が `main` に無いか、作業ツリーで変更されていると「未凍結」と書く）
3. 凍結後の変更は新しい manifest として扱い、理由と旧 manifest のハッシュを Issue に記録する。旧 manifest の結果は残す
